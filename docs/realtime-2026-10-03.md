# WebSocket թարմացումներ — 03.10.2026

**Սերվերի տեղակայման կարգավիճակ՝ սպասվում է։** Ստորև նկարագրված իրականացումը և տեղային ստուգումները պատրաստ են։ Live միջավայրում Reverb-ի մեկնարկը, HTTPS կապը և երկու առանձին սեսիաների միջև թարմացումը պետք է հաստատել տեղակայումից հետո և թարմացնել այս կարգավիճակը։

## Իրականացում

Laravel Reverb-ը և Laravel Echo-ն օգտագործում են մասնավոր `lager.updates` ալիքը՝ `data.changed` իրադարձությամբ։ Ալիքի նույնականացումը կատարվում է `POST /api/broadcasting/auth` հարցումով, Sanctum token-ով և ակտիվ օգտահաշվի ստուգմամբ։ Ազդակը բիզնես տվյալներ, անձնական տվյալներ կամ թույլտվությունների ցանկ չի փոխանցում․ յուրաքանչյուր էկրան տվյալները կրկին ստանում է իր API-ից՝ գործող թույլտվություններով և պահեստային սահմանափակումներով։

Հաջող `POST/PUT/PATCH/DELETE` API հարցումից հետո, երբ տվյալների բազայի գործարքն ավարտված է, ուղարկվում է մեկ ընդհանուր թարմացման ազդակ։ Այն ներառում է նաև ծանուցման ընթերցումը, կատալոգի և դերերի իրավունքների փոփոխությունները։ Ընթերցումները, մուտքը/ելքը, ալիքի նույնականացումը, մերժված կամ չպահպանված գործարքները ազդակ չեն ստեղծում։ Հեռարձակման խափանումը գրանցվում է log-ում և չի փոխում հաջող պահպանման պատասխանը։

Բաց էկրանները և ծանուցումները թարմացվում են ազդակով։ Միաժամանակ ստացված ազդակները միավորվում են, կապի վերականգնումը նորից ստանում է վերջին տվյալները, իսկ հին սեսիայի ուշացած պատասխանները անտեսվում են։ Ծանուցումների 45-վայրկյանանոց polling-ը գործում է միայն WebSocket կապի բացակայության դեպքում․ հաստատված կապի ժամանակ timer-ը դադարեցվում է։ Ծանուցումների ձայնի գործող կարգավորումը պահպանվում է։

## Սերվերի պահանջներ

- Տեղադրել lock ֆայլի Composer/NPM կախվածությունները, կառուցել frontend-ը։ Իրականացումը մնում է Laravel 12-ի վրա, օգտագործում է `laravel/reverb`, `laravel-echo` և `pusher-js`։ Laravel 13-ի անցումը հետաձգված է առանձին աշխատանքի համար։
- `.env`-ում միացնել `BROADCAST_CONNECTION=reverb`, սահմանել եզակի `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET`։ Գաղտնիքը պահվում է միայն սերվերում։ Հրապարակային app key-ը էջից հասանելի է frontend-ին։
- Ներքին հրապարակման և Reverb listener-ի համար օգտագործել `REVERB_HOST=127.0.0.1`, `REVERB_PORT=8080`, `REVERB_SCHEME=http`, `REVERB_SERVER_HOST=127.0.0.1`, `REVERB_SERVER_PORT=8080`։ `REVERB_ALLOWED_ORIGINS`-ում սահմանել `lager.diagen.am`-ը։ Client event-երը անջատված են։
- [lager-reverb.service](../deploy/lager-reverb.service) unit-ը տեղադրել `/etc/systemd/system/`-ում և գործարկել `systemctl daemon-reload`, ապա `systemctl enable --now lager-reverb`։ Unit-ը օգտագործում է PHP 8.2, `www-data` և `/var/domains/lager.diagen.am` աշխատանքային ուղին։
- [lager-reverb.nginx.conf](../deploy/lager-reverb.nginx.conf) հատվածը ներառել կայքի TLS server block-ում։ Հանրային `wss://lager.diagen.am/app/…` կապը փոխանցվում է loopback Reverb-ին, իսկ `/apps/` հրապարակման endpoint-ը դրսից փակված է։ Ստուգել Nginx կազմաձևը և reload անել։
- Կարգավորումների կամ կոդի փոփոխությունից հետո թարմացնել Laravel cache-երը և restart անել Reverb service-ը։ Այս ազդակները սինխրոն են՝ առանձին queue worker չեն պահանջում։

## Տեղային ստուգումներ

- PHP՝ **232 թեստ, 2,472 assertion**, բոլորը հաջող։ Ստուգված են գործարքից հետո հեռարձակումը, rollback-ը, բաց գործարքի բացառումը, մասնավոր ալիքի հասանելիությունը և transport/logging խափանումների մեկուսացումը։ Թեստերը օգտագործում են `null` կամ տեղային fake broadcaster և մեկուսացված SQLite memory տվյալների բազա։
- JavaScript՝ **83 թեստ**, բոլորը հաջող։ Իրական Echo/Pusher browser SDK-ներով առանձին թեստը ստուգում է նույն domain-ի WSS կապը, մասնավոր ալիքի նույնականացումը և ազդակի ընդունումը։
- Production frontend build-ը և `git diff --check`-ը հաջող են։

Live հաստատումը պետք է ներառի systemd service-ի կայուն աշխատանքը, WebSocket upgrade-ը և մասնավոր ալիքի բաժանորդագրությունը, երկու թույլատրված սեսիաների միջև փոփոխության անմիջական ցուցադրումը, կապի կորուստից հետո fallback-ը և վերամիացումը։

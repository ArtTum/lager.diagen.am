# Ծանուցումների տրամաբանություն — 10.10.2026

## Ուղղված խնդիրներ

Կենտրոնական պահեստի `storekeeper` դերը ուներ `requests.view` և `notifications.view`, բայց նոր պահանջի ծանուցումը սխալմամբ պահանջում էր նաև `requests.approve`։ Էրեբունիում նոր պահանջը ցանկի 9-րդ տեղում էր՝ զանգակի 8 տողանոց նախադիտումից դուրս։ Պահանջի ընթացիկ վիճակով կազմված հին ցանկը նաև կորցնում էր հաստատման ծանուցումը հավաքելուց/ուղարկելուց հետո և չէր ծանուցում կենտրոնին ստացման ու փակման մասին։

## Հասցեատերեր

Ծանուցումների համար անհրաժեշտ է `notifications.view` և համապատասխան բաժնի դիտման իրավունքը։ Դիտման իրավունքը հաստատելու իրավունք չի տրամադրում։

| Գործողություն | Ծանուցման հասցեատեր |
| --- | --- |
| Մասնաճյուղից պահանջի ուղարկում | Կենտրոնական պահեստի՝ պահանջները դիտող աշխատակիցներ |
| Կենտրոնից մասնաճյուղի համար պահանջի ուղարկում | Այդ մասնաճյուղի աշխատակիցներ և կենտրոնի մյուս դիտող աշխատակիցներ |
| Ստուգում, հաստատում/մասնակի հաստատում, մերժում, հավաքում, ուղարկման պատրաստում, ուղարկում | Նշված մասնաճյուղը և կենտրոնի մյուս դիտող աշխատակիցները |
| Մասնաճյուղում ստացման հաստատում, փակում կամ ներկայացված պահանջի չեղարկում | Կենտրոնը և նույն մասնաճյուղի մյուս դիտող աշխատակիցները |
| Սևագրի պահպանում, խմբագրում կամ չեղարկում | Նոր իրադարձության ծանուցում չի ստեղծվում |
| MIN/MAX մնացորդ | Օգտատիրոջ պահեստը՝ `stock.view` իրավունքով |
| Ժամկետներ | Մասնաճյուղը տեսնում է իր LOT-երը, կենտրոնը՝ բոլոր պահեստները, `expiry.view` իրավունքով |
| Գույքագրում | Մասնաճյուղի սեփական բաց/ներկայացված գույքագրումները։ Կենտրոնի հաստատողը տեսնում է բոլոր ներկայացվածները, այլ կենտրոնական դիտողը՝ սեփական բաց գույքագրումը |
| Տեղափոխում | Կենտրոնի հաստատողին՝ հաստատման սպասողները, ստացող պահեստին՝ ուղարկված և ընդունման սպասողները |

Գործողությունը կատարողը սեփական իրադարձության կրկնակի ծանուցում չի ստանում։ Իր ուղարկած պահանջի՝ ստուգման սպասելու ակտիվ հիշեցումը պահպանվում է։ Այլ մասնաճյուղերի պահանջների իրադարձությունները մասնաճյուղի օգտատիրոջը չեն տրամադրվում։

## Ցանկ և ընթերցում

Պահանջների իրադարձությունները վերցվում են գործողությունների պատմությունից և ցուցադրվում են վերջին 7 օրվա համար՝ անկախ պահանջի հաջորդ վիճակից։ Բաց սպասող պահանջների/ստացման ակտիվ հիշեցումները պահպանվում են նաև հին պատմության դեպքում։ Կարդացված վիճակը անձնական է։ Հին ծանուցումների բանալիները ճանաչվում են, և իրադարձությունից ակտիվ հիշեցման անցումը կարդացված ծանուցումը կրկին չկարդացված չի դարձնում։

Սկզբում չկարդացվածներն են, դրանց մեջ՝ պահանջներ/տեղափոխումներ/գույքագրումներ՝ վերջին գործողության ժամանակով։ Մնացորդների ու ժամկետների հիշեցումները հաջորդում են։ Առավելագույնը 300 տողը սահմանվում է դասավորելուց հետո, զանգակը ցույց է տալիս առաջին 8-ը։

## Կապ և ձայն

Հաջող API փոփոխությունից հետո `data.changed` դատարկ ազդակը մասնավոր `lager.updates` WSS ալիքով թարմացնում է բաց էջերն ու զանգակը։ Յուրաքանչյուր օգտատիրոջ API-ն նորից ստուգում է իր իրավունքներն ու պահեստը։ Վերամիացումը, էջ վերադարձը և պատուհանի ակտիվացումը նորից ստանում են տվյալները։ Անջատված սոկետի դեպքում ծանուցումների պահուստային թարմացումը կատարվում է 45 վայրկյանը մեկ։ Ձայնը օգտատիրոջ ընտրությամբ է, ակտիվանում է կայքում սեղմելուց/ստեղնաշար օգտագործելուց հետո, և մեկ նոր խմբի համար հնչում է մեկ անգամ։ Առաջին բեռնումը հին պատմության համար ձայն չի տալիս։ Բեռնելու սխալը զանգակում ունի կրկին փորձելու կոճակ։

Դերերի/պահեստի իրական փոփոխությունը մաքրում է նախորդ հասանելիության տվյալները։ Նույն օգտահաշվի անվան թարմացումը չի փակում զանգակը կամ ջնջում նոր ծանուցումների ձայնի հիշողությունը։

Տվյալների բազայում հավելվածից դուրս կատարված փոփոխությունը ինքնուրույն սոկետի ազդակ չի ստեղծում։ Այս համակարգը կայքի ներսի ծանուցումներ է տրամադրում. փակ կայքի համար browser push առանձին չի գործարկվում։
